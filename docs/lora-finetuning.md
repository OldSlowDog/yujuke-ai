# LoRA 场景微调（Agent 工具调用纠偏）

> Fine-tuning the 4B model to fix "intent → tool name" mapping breakages in agent tool calling.
> 本文基于真实训练 / 评估记录整理；参数为上线实测。

## 背景与动机

4B 量级模型在 Agent 工具调用上存在**「意图 → 工具名」映射断裂**：

- `fs__write` 与 `memory__write` 误用（把「记一下」当成「写文件」）；
- `verify` / `check` 验收类工具混淆；
- 记忆工具用法错误（重复调 `memory__read`、该写时不写）；
- **无工具负例缺失**：闲聊 / 问答场景仍硬要调工具。

提示词层与结构化旁白只能**治标**（约束行为但改不了权重倾向）。要在权重层根冶，需做 **LoRA 场景微调**。

## 基座与硬件

| 项 | 值 |
|----|----|
| 基座 | `rodrigomt/Qwen3.5-4B-Uncensored-Aggressive` BF16 safetensors |
| 架构 | 混合 `linear_attn` + `mamba_ssm` + `Gated DeltaNet`，`Qwen3_5ForConditionalGeneration` VLM 包装，权重在 `model.language_model.*`（无 vision 张量） |
| 硬件 | RTX 5060 Laptop **8GB**（sm_120） |
| 框架 | Unsloth 2026.10.3 + torch 2.10.0+cu130 + transformers 5.5.0 + trl 0.23.1 |
| 训练参数化 | **QLoRA**：`load_in_4bit=True` + LoRA `r=16`，仅训练 **21.23M 参数 / 0.47%** |

> 基座与线上 GGUF 同权重；微调目标是在不重训全量的前提下，把「该调哪个工具」的先验写进适配器。

## 关键工程挑战（8GB 显存）

在消费级 8GB 卡上训 4B，踩到并解决了几个真实坑：

1. **注意力静默退化**：`use_gqa_in_sdpa` 在 `mask is None` 时返 True；但 sm_120 的 EFFICIENT_ATTENTION 不支持 GQA 变体，会**静默退化到 math 注意力**并 materialize `(B,H,N,N)` fp32。修法：强制 `repeat_kv`，把注意力从 O(N²) 内存降回 O(N)。
2. **全序列 logits 爆炸**：词表 **248320**，全序列 logits fp32 巨大，而监督位只占序列 ~1%。修法：`logits_to_keep=k`（`lm_head(hidden[:, -k:])`）+ 自写 `compute_loss`，只算末尾监督段。
3. **掩码正则必须含 `<|im_end|>`**：否则模型学不会「停止」。
4. **显存碎片**：caching allocator 随样本长度变化而碎片。修法：条件 `empty_cache`（余量 >512MB 才清）+ 分块 CE；实测 `peak 5.39 GiB / max_reserved 6.98 GiB`，**全程零 OOM**。
5. **提速（最大杠杆）**：`TORCHDYNAMO_DISABLE=1` → **11×**（单步 forward 76s → 6.8s，loss 逐位一致）；配合 unsloth 专用 GC。

## 语料

**分布对齐原则**：每条样本的 `system` 提示词 + `tools` schema 必须与推理时**逐字节一致**——因此动提示词或工具集就必须重生成语料重训。

- 规模演化：**534 → 720 条**（train 607 / eval 113），**27 个工具全覆盖**，含硬负例、多轮、无工具负例（23.2%）。
- **去串味**：以「话题簇（同首句）整簇进同一侧」切分，结构上杜绝 train/eval 串味（交集恒为 0）。
- 硬负例来源为线上真实失败样本（如「生成鹈鹕踩单车 CSS 动画的网页」、贴 `/s/<token>`、「你多等一会」）。

## 训练与评估

**评估三率**（temp=0 贪心，base vs LoRA 对照）：

- ① **首调命中率**：第一次就该调的工具，是否调对；
- ② **该调不调率**：该调却没调的比例；
- ③ **不该乱调率**：不该调工具却乱调的比例（越低越好）。

| 配方 | epoch | lr | dropout | 步数 | 时长 | train_loss |
|------|-------|----|---------|------|------|-----------|
| v4 | 2 | 2e-4 | 0 | 226 | ~2h | 0.4159 |
| v5 | 1 | 1e-4 | 0.05 | 152 | ~1h20m | 0.852（刻意欠拟合） |

> v5 的 `train_loss` 升高是**故意**的：lr 减半 + dropout + 只训 1 epoch，把动作先验从过冲位拉回；判据是评估三率，不是训练 loss。

### 结果（113 条干净批：90 期望调用 + 23 期望无工具，三方对照）

| 指标 | base | v4（过冲） | v5（欠拟合） |
|------|------|-----------|-------------|
| ① 首调命中 | 42.2% | **87.8%** | 74.4% |
| ② 该调不调 | 10.0% | **2.2%** | 11.1% |
| ③ 不该乱调 | 8.7% | **26.1% ⚠️** | **8.7% ✅** |

### 结论

- **LoRA 对「意图 → 工具名」映射确有强增益**：① 从 42% 拉到 75%~88%（**+45pp** 量级）。
- **v4 过冲**：③ 反而恶化到 26%（把「不该调」也调了）。
- **v5 用「负样本 + 低训练量」把 ③ 拉回 8.7%**（与基座持平），但 ① 回落到 74.4%。
- 两端说明配方落在**「过冲 / 欠拟合」之间**，正解是 **v5 配方但 epoch 1→2**（控制变量，有效学习量 2.0）。
- **v5 错法质量高于基座**：从「跳到无关工具」（`fs__write→plan__add` ×7）变成「同族近义混淆」（`memory__write↔read`），方向对、只是学得不够细 → 需补近义工具样本。
