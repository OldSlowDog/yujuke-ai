# 工具桥契约（MCP Bridge — Tool Contract）

工具桥是 Agent 调用本地能力的唯一通道。它刻意采用 **REST 风格（非 JSON-RPC）**，用 **`X-MCP-Key` 头 + 对等 IP 白名单** 做鉴权，便于审计、限流与多语言接入。

> 本文档只描述**公开接口契约与工具能力分类**，不含任何密钥、内网地址或部署细节。

## 调用约定

```
POST /tools/call
Headers:
  Content-Type: application/json
  X-MCP-Key: <服务端校验的共享密钥>
Body:
  { "name": "<工具名>", "arguments": { ... } }

Returns:
  { "content": [ ... ], "isError": false }
```

- 工具调用**必须显式携带 `name`**，且与广播名逐字一致，否则返回「未知工具」。
- 失败的工具调用 **`isError=true`** 且**不产出引用来源**（避免幻觉地址变成「参考来源」）。
- 每次改完工具实现后需 **重新锁定哈希**（pin），否则该服务被禁用。

## 工具能力分类（16–17 个，按域分组）

| 域 | 典型能力 | 说明 |
|----|----------|------|
| 文件系统 | `read_file` / `write_file` / `edit_file` | 读写与差异编辑工作区文件 |
| 任务 | `todo`（scoped） | 计划/待办管理 |
| 网页 | `preview` / `screenshot` / `eval_page` | 渲染预览、无头截图、真浏览器交互求值（含控制台/异常捕获） |
| 记忆 | `memory__*` | 跨会话长期记忆读写 |
| 分享 | `share__open` | 生成可分享的对话/结果页（带 7 天有效期） |
| 视觉 | `vision__analyze` | 多模态图像分析（走 mmproj） |
| 系统 | 文件树 / 检索 / 健康检查 | 工作区导航与状态 |

## 安全与稳定性设计

- **路径包含校验**：签发票据前校验归一化路径位于工作区内，防止 `../../etc/passwd` 越权。
- **失败不产出来源**：避免死链/幻觉地址进入「参考来源」。
- **重复调用守卫**：同一工具 + 同参数，第 3 次拒绝、第 5 次判 stuck；写类成功会清除非写类计数（避免误伤后续操作）。
- **轮数硬上限 100 + 轮内上下文护栏**：轮内 messages 只增不减，逼近窗口即提前收尾，防爆窗。
- **工具结果只在同轮生成期累积**；跨轮靠工作记录（worklog）有界回灌，而非无限上下文。

## 设计取舍

| 选择 | 理由 |
|------|------|
| REST 而非 JSON-RPC | 语言无关、易审计、易限流；代价是需自建调用约定 |
| 头密钥 + IP 白名单 | 双因子降低泄露面；代价是部署需固定网络拓扑 |
| 扁平命名（flat naming） | 减少路由歧义；代价是工具名较长 |
