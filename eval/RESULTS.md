# 评测结果（Benchmark Results）

## 工具调用纠偏基准（LoRA 三率）

评测方法：冻结推理参数，仅换 LoRA 适配器；`temp=0` 贪心解码；在**干净评估批（113 条 = 90 期望调用 + 23 期望无工具）**上比较基座与适配器。三率定义：

- ① **首调命中率**：第一次就该调的工具是否调对（越高越好）
- ② **该调不调率**：该调却没调的比例（越低越好）
- ③ **不该乱调率**：不该调工具却乱调的比例（越低越好）

| 指标 | base | v4（过冲） | v5（欠拟合） |
|------|------|-----------|-------------|
| ① 首调命中 | 42.2% | **87.8%** | 74.4% |
| ② 该调不调 | 10.0% | **2.2%** | 11.1% |
| ③ 不该乱调 | 8.7% | **26.1% ⚠️** | **8.7% ✅** |

**读数**：

- LoRA 对「意图 → 工具名」映射有**强增益**：① 从 42% 拉到 75%~88%（约 +45pp）。
- v4 过冲：③ 恶化到 26%（把「不该调」也调了）。
- v5 用「负样本 + 低训练量」把 ③ 拉回 8.7%（与基座持平），但 ① 回落到 74.4%。
- 正解是 **v5 配方但 epoch 1→2**（控制变量实验），当前**暂停**待做。

> 详细训练配方、显存工程与结论见 [`../docs/lora-finetuning.md`](../docs/lora-finetuning.md)。

## 多步任务基准（框架）

[`run_eval.py`](./run_eval.py) + [`tasks.json`](./tasks.json) 提供 12 个多步 Agent 任务与可复现打分。在自托管环境用 `--live` 跑完后，把每任务实际工具序列写入转录文件，再用 `--score` 得到：

- **任务通过率**
- **首调命中率①**（与上表口径一致）

示例转录（`transcripts/example.json`，全通过）运行：

```bash
python run_eval.py --score transcripts/example.json
# 任务通过率   : 12/12 = 100.0%
# 首调命中率 ① : 12/12 = 100.0%
```

> 真实多步任务的数字需在装有 LoRA 适配器 + 工具桥的部署上跑出；此处框架已就绪、口径已对齐 LoRA 三率，可直接复用。
